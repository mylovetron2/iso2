1. Orchestration Là Gì?

📖 Định Nghĩa

Orchestration (Điều phối) là quá trình tự động hóa việc quản lý, phối hợp, và điều phối các services/containers/processes trong hệ thống phân tán.

Trong PMS, orchestration giúp:

  • 🔄 Tự động khởi động/dừng các services (Backend, WebSocket, Queue Workers)
  • ⚖️ Load balancing - Phân tải request đều giữa các instances
  • 🔧 Auto-scaling - Tự động tăng/giảm số lượng containers khi load thay đổi
  • 💚 Health checks - Phát hiện và restart services bị lỗi
  • 🚀 Zero-downtime deployment - Deploy không gián đoạn service
  • 📊 Resource management - Quản lý CPU, RAM cho từng service

🎯 Use Cases Trong PMS

Tình Huống Không Có Orchestration Có Orchestration
Laravel server bị crash ❌ Service down, cần restart thủ công ✅ Tự động restart trong 5s
200 users online cùng lúc ❌ Server quá tải, chậm ✅ Tự động tăng thêm 2 instances
Deploy version mới ❌ Downtime 5-10 phút ✅ Zero-downtime rolling update
Queue worker xử lý email chậm ❌ Email delay, user phàn nàn ✅ Tự động tăng thêm workers
Database backup hàng đêm ❌ Phải cron job thủ công ✅ Scheduled jobs tự động

2. Các Công Cụ Orchestration

🐳 Docker Compose

Level: Beginner-friendly

Best for: MVP, single-server

Users: 10-200


✅ Ưu điểm:
  • Cực kỳ đơn giản
  • Setup nhanh (5 phút)
  • Đủ cho MVP
  • Free 100%
❌ Nhược điểm:
  • Chỉ chạy 1 server
  • Không auto-scale
  • Manual recovery

🎻 Supervisor

Level: Beginner

Best for: Queue workers, cron jobs

Users: 10-500


✅ Ưu điểm:
  • Quản lý processes tốt
  • Auto-restart workers
  • Web dashboard
  • Dễ config
❌ Nhược điểm:
  • Không quản lý containers
  • Single-server only
  • Không load balancing

☸️ Kubernetes (K8s)

Level: Advanced

Best for: Enterprise, multi-server

Users: 500-100,000+


✅ Ưu điểm:
  • Auto-scaling mạnh mẽ
  • Multi-server cluster
  • Self-healing
  • Rolling updates
❌ Nhược điểm:
  • Cực kỳ phức tạp
  • Cần DevOps engineer
  • Chi phí cao ($200+/mo)

🐝 Docker Swarm

Level: Intermediate

Best for: Mid-size, 2-5 servers

Users: 200-1,000


✅ Ưu điểm:
  • Đơn giản hơn K8s
  • Built-in Docker
  • Load balancing tốt
  • Rolling updates
❌ Nhược điểm:
  • Ít tính năng hơn K8s
  • Community nhỏ hơn
  • Ít được dùng

💡 Khuyến Nghị Cho PMS MVP (50-200 users)

Giai đoạn 1 (Tháng 1-6): Docker Compose + Supervisor

  • ✅ Đơn giản, dễ quản lý
  • ✅ 1 người có thể handle
  • ✅ Chi phí thấp ($24/month VPS)
  • ✅ Đủ cho 50-200 concurrent users

Giai đoạn 2 (Sau 6 tháng, nếu users > 500): Kubernetes hoặc Docker Swarm

  • 📈 Scale lên nhiều servers
  • 📈 Auto-scaling based on metrics
  • 📈 High availability (99.9% uptime)

then echo " ✅ Backend: Healthy" else echo " ❌ Backend: Down (HTTP $BACKEND_STATUS)" fi # Check Redis REDIS_PING=$(docker exec pms_redis redis-cli ping 2>/dev/null || echo "FAIL") if [ "$REDIS_PING" = "PONG" ]; 6. Supervisor - Process Manager

🎻 Tại Sao Cần Supervisor?

Docker Compose chỉ quản lý containers. Supervisor quản lý processes BẾN TRONG container (như queue workers).

📦 Cài Đặt Supervisor

# Trong Laravel container apt-get update apt-get install -y supervisor # Tạo config file nano /etc/supervisor/conf.d/laravel-worker.conf

⚙️ Supervisor Config

; /etc/supervisor/conf.d/laravel-worker.conf ; Queue Worker [program:laravel-worker] process_name=%(program_name)s_%(process_num)02d command=php /var/www/html/artisan queue:work --sleep=3 --tries=3 --max-time=3600 autostart=true autorestart=true stopasgroup=true killasgroup=true user=www-data numprocs=3 ; Chạy 3 workers redirect_stderr=true stdout_logfile=/var/www/html/storage/logs/worker.log stopwaitsecs=3600 ; Reverb WebSocket Server [program:reverb] command=php /var/www/html/artisan reverb:start --host=0.0.0.0 --port=8080 autostart=true autorestart=true user=www-data redirect_stderr=true stdout_logfile=/var/www/html/storage/logs/reverb.log ; Scheduler (Laravel Cron) [program:laravel-scheduler] command=/bin/sh -c "while [ true ]; do (php /var/www/html/artisan schedule:run --verbose --no-interaction &); sleep 60; done" autostart=true autorestart=true user=www-data redirect_stderr=true stdout_logfile=/var/www/html/storage/logs/scheduler.log

🚀 Supervisor Commands

# Start Supervisor supervisord -c /etc/supervisor/supervisord.conf # Check status supervisorctl status # Output: # laravel-worker:laravel-worker_00 RUNNING pid 12345, uptime 1:23:45 # laravel-worker:laravel-worker_01 RUNNING pid 12346, uptime 1:23:45 # laravel-worker:laravel-worker_02 RUNNING pid 12347, uptime 1:23:45 # reverb RUNNING pid 12348, uptime 1:23:45 # laravel-scheduler RUNNING pid 12349, uptime 1:23:45 # Restart all workers supervisorctl restart laravel-worker:* # Stop specific worker supervisorctl stop laravel-worker:laravel-worker_00 # Reload config supervisorctl reread supervisorctl update

✅ Lợi Ích Supervisor

  • 🔄 Auto-restart workers khi bị crash
  • 📊 Monitor status của tất cả processes
  • ⚡ Scale số lượng workers dễ dàng (thay numprocs=3 → numprocs=5)
  • 📝 Logs tập trung tất cả workers
  • 🎛️ Web UI để quản lý (optional)

🔍 Troubleshooting Examples

❌ Problem: Worker keeps restarting

#!/bin/bash # auto-scale.sh - Tự động scale based on metrics # Get current CPU usage CPU_USAGE=$(docker stats --no-stream --format "{{.CPUPerc}}" pms_backend | sed 's/%//') # Get queue size from Redis QUEUE_SIZE=$(docker exec pms_redis redis-cli LLEN queues:default) if [ $(echo "$CPU_USAGE > 80" | bc) -eq 1 ] || [ $QUEUE_SIZE -gt 100 ]; then echo "High load detected! #!/bin/bash # advanced-auto-scale.sh - Smart scaling với metrics và alerts SLACK_WEBHOOK="https://hooks.slack.com/services/YOUR/WEBHOOK/URL" EMAIL_ALERT="admin@example.com" # Function: Send Slack notification send_slack() { MESSAGE=$1 curl -X POST $SLACK_WEBHOOK \ -H 'Content-Type: application/json' \ -d "{\"text\":\"🚨 PMS Alert: $MESSAGE\"}" } # Function: Get metrics get_metrics() { # CPU usage CPU=$(docker stats --no-stream --format "{{.CPUPerc}}" pms_backend | sed 's/%//') # Memory usage MEM=$(docker stats --no-stream --format "{{.MemPerc}}" pms_backend | sed 's/%//') # Queue size QUEUE=$(docker exec pms_redis redis-cli LLEN queues:default) # Failed jobs FAILED=$(docker exec pms_redis redis-cli LLEN queues:default:failed) # Worker count WORKERS=$(docker ps --filter "name=pms_queue_worker" --format "{{.Names}}" | wc -l) # Response time (avg last 100 requests) RESPONSE_TIME=$(docker exec pms_nginx tail -100 /var/log/nginx/access.log | \ awk '{print $NF}' | awk '{sum+=$1; count++} END {print sum/count}') echo "CPU=$CPU MEM=$MEM QUEUE=$QUEUE FAILED=$FAILED WORKERS=$WORKERS RT=$RESPONSE_TIME" } # Function: Scale workers scale_workers() { NEW_COUNT=$1 REASON=$2 echo "[$(date)] Scaling workers to $NEW_COUNT - Reason: $REASON" docker compose up -d --scale queue_worker=$NEW_COUNT send_slack "Scaled queue workers to $NEW_COUNT. Reason: $REASON" } # Main monitoring loop while true; do METRICS=$(get_metrics) eval $METRICS # Parse metrics into variables echo "[$(date)] Metrics: CPU=${CPU}%, MEM=${MEM}%, Queue=$QUEUE, Workers=$WORKERS, RT=${RESPONSE_TIME}ms" # CRITICAL: Failed jobs > 10 if [ $FAILED -gt 10 ]; then send_slack "⚠️ CRITICAL: $FAILED failed jobs detected! Investigate immediately." echo "$FAILED failed jobs" | mail -s "PMS Alert: Failed Jobs" $EMAIL_ALERT fi # SCALE UP conditions if [ $(echo "$CPU > 80" | bc) -eq 1 ] && [ $WORKERS -lt 8 ]; then scale_workers $((WORKERS + 2)) "High CPU: ${CPU}%" elif [ $QUEUE -gt 200 ] && [ $WORKERS -lt 8 ]; then scale_workers $((WORKERS + 3)) "High queue size: $QUEUE jobs" elif [ $(echo "$RESPONSE_TIME > 2000" | bc) -eq 1 ] && [ $WORKERS -lt 6 ]; then scale_workers $((WORKERS + 2)) "Slow response: ${RESPONSE_TIME}ms" # SCALE DOWN conditions elif [ $(echo "$CPU < 30" | bc) -eq 1 ] && [ $QUEUE -lt 10 ] && [ $WORKERS -gt 3 ]; then scale_workers $((WORKERS - 1)) "Low load: CPU=${CPU}%, Queue=$QUEUE" fi # WARNING alerts if [ $(echo "$MEM > 85" | bc) -eq 1 ]; then send_slack "⚠️ WARNING: High memory usage: ${MEM}%" fi if [ $QUEUE -gt 100 ]; then send_slack "⚠️ WARNING: Queue backlog: $QUEUE jobs pending" fi sleep 60 # Check every minute done

10. Best Practices

✅ Orchestration Checklist

📋 MVP Phase (Tháng 1-6):

  • ☑️ Docker Compose với restart policies
  • ☑️ Health checks cho tất cả services
  • ☑️ Resource limits (CPU, Memory)
  • ☑️ Supervisor cho queue workers
  • ☑️ Monitoring script (CPU, Memory, Queue size)
  • ☑️ Automated backups (daily)
  • ☑️ Log aggregation (centralized logs)

📈 Scale Phase (Tháng 7+):

  • ☑️ Manual scaling script (CPU/Queue based)
  • ☑️ Multiple VPS với load balancer (nếu cần)
  • ☑️ Redis Sentinel cho HA
  • ☑️ PostgreSQL replication
  • ☑️ CDN cho static files

🚀 Enterprise Phase (Users > 500):

  • ☑️ Kubernetes cluster
  • ☑️ Horizontal Pod Autoscaler
  • ☑️ Service mesh (Istio)
  • ☑️ Prometheus + Grafana monitoring
  • ☑️ ELK stack cho logs

🎯 Key Takeaways

  1. Start Simple: Docker Compose đủ cho MVP (50-200 users)
  2. Add Supervisor: Quản lý queue workers và cron jobs
  3. Monitor Metrics: CPU, Memory, Queue size, Response time
  4. Manual Scale First: Test scaling manually trước khi auto
  5. Kubernetes Later: Chỉ khi thực sự cần (> 500 users)
